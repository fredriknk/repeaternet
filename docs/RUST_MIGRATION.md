# RepeaterNet Python-to-Rust migration

Baseline: Python tree at commit `18b7cee`. This inventory describes the supported web application, including engine functionality exercised independently of HTTP. [Development](DEVELOPMENT.md), the [user guide](USER_GUIDE.md), and the Python/Node tests define the current workflows. Dated plans in `docs/history` provide background. The retired Qt UI, desktop formats, contour renderer, legacy Deygout model, and opportunistic import of loose pre-catalog files are outside the baseline.

The release target is a single distributable Windows executable which starts a local dashboard and opens the default browser when launched interactively. Keep headless/self-hosted operation and make Linux a supported build where feasible. Retain `--host`/`--port` and current environment-variable semantics. Define browser opening, an explicit headless switch, writable data location for direct launches, and port-conflict behavior as part of launcher design. Use a stable URL and host name because existing workspace selection is tied to the browser cookie and UI preferences are origin-scoped. Bind successfully before opening the browser. Test the binary from Explorer and a terminal on a clean system.

## Wire conventions and shared DTOs

The implementation reference is [web.py](../src/rf_router_planner/web.py), with dashboard request construction in [app.js](../src/rf_router_planner/web_assets/app.js). Tables below list application handlers, static mounts, and the framework-generated discovery endpoints. Capture full oracle payloads for nested records before porting each group. Keep typed domain models and Serde DTOs distinct where JSON defaults, nullable values, or compatibility require it.

- Successful JSON actions normally return HTTP 200, including asynchronous job starts. Preserve `{"detail": ...}` errors. Important classes are 400 malformed terrain upload, 401 auth/workspace, 403 origin, 404 missing or out-of-scope resource, 409 busy/stale/incompatible request, 413 bounded report/export, 422 input or readiness, 429 capacity, 502 CoreScope upstream, and 503 submission failure where implemented. Snapshot the framework-generated validation envelope separately from explicit string details.
- Plan endpoints `a` and `b` use `[latitude, longitude]`. Geographic map bounds use `[south, west, north, east]`, GeoJSON and the drawn coverage ring use `[longitude, latitude]`, and projected bounds use `[min_x,min_y,max_x,max_y]` in metres. Transforms use XY axis order. Several readiness overlays use Leaflet latitude-first coordinates.
- The web plan uses `format: "repeaternet-web"`, `version: 1`, `a`, `b`, `rf`, `candidates`, `terrain`, `coverage`, `coverage_targets`, `known_routers`, `manual_routers`, and `search_effort`. Server-side start adds `resolved_search`. Older saved plans can omit newer fields. Preserve unknown outer plan data through the catalog and project download. Settings merge with model defaults and apply enum, type, and range checks in `settings()`, `validate()`, and `parse_coverage_settings()`. Non-finite values emitted by `encode()` become JSON null. Preserve meaningful nulls in profile arrays and margins, and the string form of integer dictionary keys such as LoRa SF thresholds.
- [settings.py](../src/rf_router_planner/models/settings.py), [site.py](../src/rf_router_planner/models/site.py), [link.py](../src/rf_router_planner/models/link.py), [network.py](../src/rf_router_planner/models/network.py), and [coverage.py](../src/rf_router_planner/models/coverage.py) enumerate model fields, defaults, and enums. Freeze complete default RF/candidate and coverage records with oracle fixtures. Distinguish `rf_propagation` from `strict_los`, `bullington`, the four optimization priorities, three infrastructure policies, two road classes, site kinds/origins/height references, and optional/required/excluded router policy.
- Job data uses `state,stage,done,total` where applicable, and route identity uses `job_id,input_revision,snapshot_version`. Preserve resolved search scope, queue and cancellation states, progress units where supplied, and separate coverage terrain, coverage run, and inspection records. Route data includes certified partial snapshots and can reach `stopped` with `search_complete:false`. Treat a final status as observably committed only after its persistence work completes.
- Route result fields are `found,router_count,existing_router_count,proposed_router_count,route,links,diagnostics,elapsed_seconds,search_complete,requested_path_count,achieved_path_count,job_id,input_revision,snapshot_version,rf_settings,candidates,active_alternative_id,alternatives` with optional `road_polylines`. `route` contains all active solution sites. Links include forward/reverse budgets, clearances, obstacles, optional profile arrays, and `worst_margin_db`. Alternatives contain a stable topology ID, name, all router counts, minimum margin, total link and primary distances, path counts, resilience, completion/selection flags, and primary path sites. When roads exist, alternatives index the shared polylines and expose nearest-road distances keyed by router ID.
- Standard coverage request supplies `snapshot_version,alternative_id,settings` and `map_bounds` in view mode. It needs a current certified route and matching inputs; starting a persisted run also requires saved coverage settings. `settings` contains mode, mesh/view/drawn area, WGS84 polygon, buffer, cell size, profile step/sample cap, source/cell/evaluation limits, client RF profile, endpoint participation and selected repeater IDs. Defaults include a 1 km cell, 5 km buffer, 200 m profile step, 4,096 cells and samples per profile, 64 sources, and 250,000 evaluations. Validators cap the grid and profiles at 16,384, require at least three samples, and bound source selections, geometry, and physical radio values. Coverage cells preserve row-major index, x/y, lat/lon, state, source/unknown/unresolved counts, best source/margin, and directional validity/margins/rejection per source.

## Coverage, scenarios and target algorithms

1. Build the grid in the terrain CRS. Mesh default includes the route-width square-ended corridor and buffers around sites/clients, while mesh without client-area extension falls back to buffered source bounds. View uses current map bounds. Drawn area validates and projects its closed ring. Compute north-to-south, west-to-east cell centres and WGS84 render coordinates. Mask by area geometry, preserve outside cells explicitly, and increase spacing using the current ceil-based formula to fit both cell and source×cell budgets. Estimates, previews, jobs, inspections and terrain preparation must agree on these assumptions.
2. Evaluate directional link budgets from each eligible repeater or opted-in endpoint to the handheld profile. Select downlink, uplink or two-way usability by mode. Overlap and best-source displays use two-way data. Keep margins/validity for all evaluated sources. Record an independently detectable profile sample cap with effective spacing at least terrain resolution. Cap overflow is `unresolved` with `profile_sample_limit` and a missing margin rather than silently coarsening. Distinguish `outside_area,not_evaluated,unknown_terrain,unresolved,covered,uncovered`; any valid source can establish coverage even when another source is unknown/unresolved. Preserve per-source uncertainty counts and cancellation before committing incomplete cells. The default stream batch is 128 cells.
3. Exact inspection evaluates the selected point in the saved or current context using the candidate final profile spacing floor and the coverage sample cap. It samples ground at the click independent of the grid mask, ranks sources by two-way validity, then descending margin and ID, and regenerates the selected source's detailed profile when possible. Return the selected source's connected component based on valid solution links. Retain all directional results and profile-cap diagnostics. Cancellation checks apply across computation and publication, including delayed autosave and delayed job-ID delivery.

Assess polygons using saved grid cell intersections and projected areas. Separate unknown, unresolved, outside analysis, failed and passing measures with coverage and reference assumptions.
